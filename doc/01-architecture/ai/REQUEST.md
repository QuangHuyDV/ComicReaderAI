- **Document:** AI Architecture / Request
- **Version:** 1.0.0
- **Status:** Draft
- **Owner:** CRAI Architecture

---

# Purpose

This document defines the canonical request object used throughout the CRAI AI Pipeline.

Every stage receives and produces structured data through well-defined contracts. The AI Request is the primary contract that carries all information required for AI processing while remaining independent of any specific provider.

---

# Design Principles

- Immutable during processing
- Provider independent
- Serializable
- Versioned
- Traceable
- Extensible

---

# Request Lifecycle

```text
Capture
    │
    ▼
Build AI Request
    │
    ▼
Enrich Context
    │
    ▼
Route
    │
    ▼
Execute
```

---

# Request Structure

```text
AI Request
├── Metadata
├── Input
├── Context
├── Prompt
├── Model Requirements
├── Execution Policy
├── Budget
└── Trace Information
```

---

# Metadata

Metadata identifies the request.

Fields may include:

- Request ID
- Session ID
- User ID (optional)
- Timestamp
- Request Version
- Correlation ID

---

# Input

The original content supplied to the pipeline.

Supported input types:

- Image
- OCR Text
- Plain Text
- Mixed Content

Input metadata may include:

- Language
- Source
- Resolution
- Page Number

---

# Context

Context enriches AI quality.

Examples:

- Previous pages
- Character memory
- Glossary
- Reading history
- User preferences
- Project configuration

Context is built before prompt generation.

---

# Prompt

The request references the prompt generated by the Prompt Builder.

Components:

- System Prompt
- Developer Prompt
- User Prompt
- Context Injection
- Formatting Instructions

---

# Model Requirements

The routing layer evaluates requirements such as:

- Capability
- Preferred Model
- Minimum Context Window
- Streaming Support
- Tool Calling Support
- Offline Requirement

These requirements do not directly select a provider.

---

# Execution Policy

Execution policy defines runtime behavior.

Examples:

- Timeout
- Retry Count
- Retry Strategy
- Fallback Allowed
- Validation Required
- Streaming Enabled

---

# Budget

Budget constraints may include:

- Maximum Cost
- Maximum Tokens
- Maximum Latency
- Daily Budget
- Monthly Budget

The routing layer must respect these limits.

---

# Trace Information

Trace fields support observability.

Examples:

- Trace ID
- Parent Span
- Stage History
- Retry Count
- Provider Attempts

---

# Validation

Every request is validated before execution.

Validation includes:

- Required fields
- Schema version
- Supported capabilities
- Budget limits
- Context size
- Prompt size

Invalid requests are rejected before reaching the model.

---

```text

      ▼

      ▼
OCR
      │
      ▼
Context Builder
      │
      ▼
Prompt Builder
      │
      ▼
AI Request
      │
      ▼
Routing
      │
      ▼
Model Execution
```

---

# Failure Handling

Request failures include:

- Invalid schema
- Missing input
- Context overflow
- Prompt overflow
- Budget exceeded
- Unsupported capability

Failures are reported through the Runtime error model and Diagnostics.

---

# Architecture Invariants

1. Every AI execution begins with a validated AI Request.
2. The request format is provider independent.
3. Request objects are immutable during stage execution.
4. All routing decisions are based on request metadata and requirements.
5. Budget constraints are enforced before model execution.
6. Trace information follows the request throughout the pipeline.
7. Requests are versioned to maintain compatibility.
